# 오늘한칸

노션에서 쓰던 개인 일정·실행 시스템을 웹앱으로 옮기는 프로젝트입니다.

배포 주소: https://greejiu.github.io/onekan/

## 현재 구현된 기능

- Supabase 이메일 로그인 / 회원가입과 계정별 동기화
- 집: 오늘 달성률, 날씨, D-DAY, 지금 할 일, 오늘 계획, 다가오는 일정, 언젠가 할일
- 일정: 월 / 주 / 일 캘린더와 목록, 반복 일정, Google 캘린더 읽기 전용 표시
- 할일: 날짜 있음 / 언젠가 할일, 반복, 하위 할일, 프로젝트 연결
- 습관: 캘린더 / 목록, 반복 주기와 기간, 완료 기록
- 프로젝트: 프로젝트 / 목표 / 정체성 연결, 상태별 보기, 계획 항목, 연결 북마크
- 시간추적: 스톱워치 / 뽀모도로, 직접 기록과 과거 기록
- 리포트: 주 / 월 전환, 집중시간, 완료 횟수, 활동일, 날짜별 흐름과 시간 분배
- 설정: 집 배경과 테마, 날씨 지역, 타임라인 범위, 영역, 효과음
- 데이터 백업 / 복원

'기록'과 '태그' 메뉴는 현재 자리만 마련되어 있고 내용은 후속 구현 대상입니다.

## 핵심 동작 규칙

- 오늘의 경계는 새벽 3시입니다.
- 일정에는 완료 체크가 없고, 할일과 습관만 완료할 수 있습니다.
- 반복 할일의 다음 회차는 현재 회차를 완료한 뒤 생성됩니다.
- 프로젝트는 일반 할일이 생기면 '시작 전'에서 '진행 중'으로 바뀝니다.
- 목표는 연결된 프로젝트 유무에 따라 '시작 전' / '진행 중'을 맞춥니다.
- '완료'와 '보관' 상태는 자동으로 덮어쓰지 않습니다.
- Google 캘린더는 읽기 전용이며, 기본 캘린더 외에는 사용자가 눈 아이콘을 켠 것만 표시합니다.

전체 제품·개발 규칙은 [현재 규칙](docs/current-rules.md)을 참고합니다.

## 데이터와 저장

Supabase 프로젝트 'when-did-i-do-it'의 Auth를 함께 사용하므로 기존 ‘그거 언제 했더라’ 계정으로도 로그인할 수 있습니다.

오늘한칸 데이터는 'onekan_state' 테이블에 사용자별 JSON 상태로 저장됩니다. RLS로 각 사용자는 자기 데이터만 읽고 쓸 수 있습니다. 앱의 상태 읽기·변경은 'js/state-store.js'의 공용 store를 사용하며 최신 서버 상태 병합과 탭 내 쓰기 직렬화를 거칩니다.

Google 캘린더 연결용 테이블과 Edge Function은 별도로 사용합니다. 설정 방법은 [Google 캘린더 연동 안내](docs/google-calendar-setup.md)를 참고합니다.

## 주요 구조

- 'index.html' — 화면 마크업과 로드 순서
- 'css/' — 공통·기능별 반응형 스타일
- 'js/app.js' — 기본 상태와 핵심 앱 동작
- 'js/unified-workspace.js' — 일정·할일·습관·타임라인 작업공간
- 'js/state-store.js' — 'onekan_state' 공용 읽기·병합·저장
- 'js/project-*.js' — 프로젝트·목표·정체성
- 'js/tracking-*.js' — 시간추적 통계
- 'scripts/*-regression.mjs' — 기능별 회귀 검사
- 'supabase/' — 마이그레이션과 Google 캘린더 Edge Function
- 'docs/' — 사용자·제품 문서
- 'claude/' — 설계 검토와 기술 정리 문서

## 변경 검증과 배포

Pull Request와 'main' push에서 다음 검사를 실행합니다.

- JavaScript 문법 검사
- 기능별 회귀 검사
- 변경한 JS/CSS의 캐시 버전 검사
- 통합 렌더 스모크 검사

'.github/workflows/pages.yml'이 'main' 변경 시 GitHub Pages 배포를 시도합니다.
