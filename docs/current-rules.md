# 오늘한칸 현재 규칙

기준일: 2026-09-05

이 문서는 **현재 'main'에서 실제로 동작하는 규칙**을 기록합니다. 아이디어나 예정 기능은 현재 규칙과 섞지 않습니다. 동작이 바뀌면 관련 코드·회귀 검사와 함께 이 문서도 갱신합니다.

## 1. 항목 구분

### 일정

- 특정 날짜 또는 시간에 발생하는 약속과 사건입니다.
- 완료 체크박스를 사용하지 않습니다.
- 하루 종일 또는 시작·종료 시간을 가질 수 있습니다.
- 반복 없음 / 매일 / 평일 / 매주 / 사용자 지정 반복을 사용할 수 있습니다.
- Google 캘린더에서 가져온 일정은 읽기 전용입니다.

### 할일

- 완료 여부를 기록하는 실행 항목입니다.
- 날짜가 있으면 해당 날짜의 할일, 날짜가 없으면 '언젠가 할일'입니다.
- 시간에 배치할 수 있고 프로젝트를 연결할 수 있습니다.
- 하위 할일을 둘 수 있습니다.
- 하위 할일을 모두 완료하면 상위 할일도 완료됩니다.
- 일반 할일 완료와 하위 할일 전체 완료에는 같은 계열의 완료 효과음을 사용합니다.

### 습관

- 반복 실행과 날짜별 완료 기록이 필요한 항목입니다.
- 시작일·종료일과 반복 주기를 가질 수 있습니다.
- 일정이나 일반 할일과 별도의 습관 화면에서 관리합니다.
- 완료 기록은 회차별로 보존합니다.

## 2. 날짜와 반복

- 앱의 하루 경계는 **새벽 3시**입니다. 새벽 3시 전의 완료는 전날 기록으로 계산합니다.
- 반복 할일은 미리 여러 회차를 늘어놓지 않습니다.
- 현재 반복 할일을 완료하면 **완료한 날짜를 기준으로** 다음 회차를 생성합니다.
- 완료를 취소할 때 자동 생성된 다음 회차가 아직 미완료라면 그 회차도 제거하고 원래 회차를 복원합니다.
- 반복 종료일을 지난 다음 회차는 만들지 않습니다.
- 월 반복에서 해당 일이 없는 달은 그 달의 마지막 날로 맞춥니다.
- 반복 항목의 한 회차만 바꾼 정보는 다른 날짜의 회차를 임의로 덮어쓰지 않아야 합니다.

## 3. 화면 표시

### 집

- 오늘 달성률은 오늘의 완료 가능한 항목을 기준으로 표시합니다.
- 오늘 계획은 목록 / 타임라인으로 전환할 수 있습니다.
- 일정·할일·습관과 시간추적 기록을 같은 흐름에서 볼 수 있습니다.
- 시간추적 기록은 보기 / 숨기기를 사용자가 선택합니다.
- 다가오는 일정과 언젠가 할일은 별도 카드로 표시하고 각각 접을 수 있습니다.
- '지금 할 일'에서는 선택한 상위 할일과 하위 할일을 관리합니다.

### 일정·할일·습관

- 현재 사이드바에는 일정, 할일, 습관이 각각 별도 메뉴로 존재합니다.
- 일정은 캘린더 / 목록, 할일은 캘린더 / 목록, 습관은 캘린더 / 목록을 지원합니다.
- 일정과 할일을 한 메뉴로 합치는 안은 현재 'main'의 실제 동작이 아니므로 이 문서에서는 확정 규칙으로 취급하지 않습니다.

### 시간추적과 리포트

- 시간추적은 스톱워치 / 뽀모도로를 지원합니다.
- 기록 이름은 할일을 선택하거나 직접 입력할 수 있습니다.
- 리포트는 저장 데이터를 수정하지 않고 읽기 전용으로 집계합니다.
- 주 / 월 범위에서 집중시간, 완료 횟수, 활동일, 날짜별 흐름과 시간 분배를 표시합니다.

### 미구현 메뉴

- '기록'과 '태그'는 메뉴와 빈 화면만 있습니다.
- 실제 기능이 생기기 전에는 완료 기능으로 안내하지 않습니다.

## 4. 프로젝트·목표·정체성

- 연결 구조는 **정체성 → 목표 → 프로젝트 → 할일·습관**입니다.
- 연결된 할일·습관에는 북마크를 표시하고 북마크에서 연결 구조를 확인할 수 있습니다.
- 프로젝트 상태는 '시작 전(before)' / '진행 중(doing)' / '완료(done)' / '보관(archived)'입니다.
- 프로젝트에 반복 항목이 아닌 일반 할일이 하나라도 생기면 '시작 전'에서 '진행 중'으로 자동 변경합니다.
- 프로젝트의 재시작 상태는 미완료 일반 할일이 있으면 '진행 중', 없으면 '시작 전'입니다.
- 목표는 보관되지 않은 연결 프로젝트가 있으면 '진행 중', 없으면 '시작 전'으로 맞춥니다.
- '완료'와 '보관'인 프로젝트·목표는 자동 상태 조정에서 제외합니다.
- 보관은 사용자가 직접 지정하는 상태입니다.

## 5. Google 캘린더

- 각 사용자가 자기 Google 계정을 연결합니다.
- 연동은 읽기 전용이며 오늘한칸에서 Google 일정을 수정하거나 삭제하지 않습니다.
- Google 캘린더의 일정 색상을 그대로 사용합니다.
- 기본 캘린더는 처음부터 표시합니다.
- 다른 캘린더는 사용자가 눈 아이콘을 켠 경우에만 표시합니다.
- 연결 해제는 오늘한칸의 Google 연결만 끊으며 원본 Google 일정은 건드리지 않습니다.

## 6. 입력과 조작

- 인라인 입력은 Enter로 저장하는 흐름을 기본으로 합니다.
- 빈 목록·날짜·시간 영역을 통한 추가 흐름을 유지합니다.
- 데스크톱 우클릭과 모바일 길게 누르기는 항목별 추가 작업 메뉴로 사용합니다.
- 이동 손잡이 또는 정해진 드래그 영역을 사용하고 텍스트 클릭·체크 동작과 드래그가 충돌하지 않아야 합니다.
- 항목을 시간대에 놓을 공간이 없으면 실제 개수를 단정하지 않고 '이 시간대엔 더 넣을 자리가 없어요.'라고 안내합니다.

## 7. 저장 규칙

- 런타임에서 'onekan_state'를 직접 select / insert / update / upsert하지 않습니다.
- 모든 상태 읽기·변경·구독은 'onekanStateStore.read() / mutate() / subscribe()'를 사용합니다.
- 쓰기는 Promise queue로 현재 탭 안에서 직렬화합니다.
- 지원 브라우저에서는 Web Locks API로 같은 브라우저의 여러 탭 쓰기도 직렬화합니다.
- 저장 직전에 서버 최신 상태를 다시 읽고 base / local / remote 3-way merge를 수행합니다.
- ID가 있는 배열은 항목 단위로 병합합니다.
- 같은 값 하나를 양쪽이 동시에 다르게 바꾼 충돌은 현재 실행 중인 local 변경을 우선합니다.
- 다른 기기의 완전 동시 쓰기는 DB revision/RPC 잠금이 없어 충돌 가능성이 남아 있습니다.
- 내부 병합용 base token은 DB와 백업 history에 저장하지 않습니다.
- 백업 history 테이블은 현재 상태 store와 별도 보관소로 유지합니다.

## 8. 개발·변경 규칙

- 결님이 기능 범위, 우선순위, 화면 방향을 최종 결정합니다.
- 구현 전 현재 'main'의 실제 코드와 기존 합의를 함께 확인합니다.
- 한 번에 관련 없는 화면까지 넓혀 바꾸지 않습니다.
- 기존 사용자 데이터 구조를 깨는 변경은 별도 마이그레이션·복구 방안 없이 적용하지 않습니다.
- 기능을 바꾸면 해당 동작의 회귀 검사를 추가하거나 갱신합니다.
- 모든 PR과 'main' push에서 JavaScript 문법, 회귀 검사, 캐시 버전, 렌더 스모크 검사를 통과해야 합니다.
- JS/CSS를 수정하면 그 파일을 참조하는 모든 로컬 URL의 '?v=N'도 함께 올립니다.
- 문서의 '현재', '예정', '아이디어'를 구분합니다.
- Claude 문서는 리뷰·설계 검토 자료로 사용하며 실제 구현 상태는 코드와 회귀 검사를 기준으로 판단합니다.
